## Описание проекта

TaskanaApp1 - это веб-приложение, разработанное с использованием React и Vite. Проект представляет собой современное приложение для управления задачами.

Подробное описание реализованного функционала: [IMPLEMENTATION.md](docs/IMPLEMENTATION.md)

## Установка и настройка

### Предварительные требования

- Node.js (рекомендуется версия 18 или выше)
- npm (поставляется вместе с Node.js)

### Установка зависимостей

```bash
npm ci
```

#### Примечание по безопасности

Рекомендуется использовать `npm ci` вместо `npm install` для установки зависимостей, особенно в продакшене. `npm ci` обеспечивает:

- Установку точно тех версий, что зафиксированы в `package-lock.json`
- Повышенную безопасность (игнорирует `package.json`)
- Более быструю и чистую установку

### Запуск в режиме разработки

```bash
npm run dev
```

После запуска приложение будет доступно по адресу: http://localhost:5173

### Сборка проекта

```bash
npm run build
```

Собранная версия будет находиться в директории `dist/`

ThemeToggle.jsx, CreateAndTheme.jsx используются только в хедере,
поэтому размещены в папке header (не в общих компонентах).

## Заметки разработчика

Поумничал и вынес все стили шрифтов в файл typography.css, теперь приходиться прописывать стили в каждом модуле через шаблонные строки:

```jsx
className={`${styles.button} ${typography.buttonText}`}
className={`heading-h1 ${isActive ? 'active' : ''}`}
className={styles.button + ' heading-h1'}
```

или вот так:

```jsx
className={[
  typographyStyles.headingH1,
  additionalStyles.specialHeading
].join(' ')}
```

Подключать typography.css в каждый компонент не надо, т.к. он подключен глобально в App.jsx

А ещё можно сделать утилиту и поместить её в папку utils:

```typescript
export function cn(...classes: (string | false | null | undefined)[]): string {
  return classes.filter(Boolean).join(' ');
}
```

и писать стили в компонентах вот так:

```jsx
className={cn(styles.button, typography.buttonText, isPrimary && styles.primary)}
```

Но так ведь нельзя, это похоже на стороннюю библиотеку cn и будет расценено как хулиганство.

Позже мне такой подход со стилями показался излишним, но для тренировки я продолжал это использовать.

### Дополнительные заметки

- **ThemeSwitcher** положил в папку header, т.к. он используется в нём, что бы было всё в одном месте.

- В TaskProvider

  Если нужно показать тестовые данные, то раскомментировать эту строку:
  // const [tasks, setTasks] = useState(initialTasks);

  и закомментировать вот эту:
  const [tasks, setTasks] = useState([]);

  Проблема, которую решает js код в index.html:

  FOUC (Flash of Unstyled Content) — вспышка белого фона при загрузке приложения.
  Вот что происходит без этого кода:

  - Браузер загружает HTML → показывает белый фон (по умолчанию).
  - Загружается CSS → применяются стили темы.
  - Загружается JavaScript → определяется тема пользователя.
  - Применяется правильная тема → фон меняется на тёмный.
  - Между шагами 1 и 4 пользователь видит неприятную вспышку белого фона.

Почему код вынесен в HTML:

- Этот код выполняется до загрузки основного JavaScript бандла, поэтому:
- Тема определяется мгновенно при загрузке HTML.
- CSS переменные применяются сразу.
- Никакой вспышки белого фона.
